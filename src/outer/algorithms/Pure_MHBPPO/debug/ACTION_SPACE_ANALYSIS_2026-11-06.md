# Pure-MHBPPO：时间动作可行域与熵退火的优先级

结论：若仅调节学习参数，连续熵退火仍是首个消融；若允许利用当前已知物理结构，应优先处理时间动作的条件可行化。原实现只施加单变量区间，未排除大量互相冲突的时间组合。2026-11-06 已实现保留全部时间头的条件解码，并通过边界、概率契约和真实短训练验证，尚未验证 5000 轮收敛。进一步将 14 个时间变量解析消去仍是待实施的独立结构变体。

## 1. 当前区间已经保证什么

`pure_env.py:_bounds()` 已保证速度范围、角度范围、功率上限、波束范数上限，并将 UAV/CU 卸载时间分别映射至大致 `(0, D_u-d_s)`、`(0, D_j)`。但它未利用匹配、已选功率/波束、任务量和共享 BS 算力构建联合时间域。

数学上排除动作的标准应是：它不可能补全为满足原硬约束的当前槽动作。低 reward、历史上很少被选或在一个快照中经常失败，均不足以证明该区间必然不可行。

- 高飞行速度通常能耗高，不等于物理不可行，不能据经济速度 5.43 m/s 将 `[5,40]` 任意截成 `[5,10]` 并声称无损。
- 大 CU 功率帮助上传，又可能影响感知和 UAV 上传；不能只凭一次失败判定某个固定功率区间永远无效。
- 波束各实虚分量经归一化后共同决定方向。逐维任意裁窄可能排除有效方向。
- 以下时间条件可以由代码约束直接推导，属于更适合先处理的部分。

## 2. 必然不可行的时间组合

记 UAV 感知时长为 `d_s`，UAV 卸载时间为 `u_i`，CU 卸载总时间为 `c_j`，UAV/CU 截止时间为 `D_u,D_j`；CU 任务比特数为 `L_j`，每比特计算量为 `C_j`，共享 BS 总算力为 `F_max`。

### 2.1 任务新鲜度产生匹配相关的下界

如果 UAV i 唯一匹配 CU j，则必须满足：

`c_j >= d_s + u_i`。

例如 `d_s=0.1s,u_i=0.05s` 时，`c_j<0.15s` 的组合必然违反新鲜度，功率再大也无法补救。但同一个 CU 若未被匹配，不能把这条 0.15s 下界强加给它。因此需要条件边界，而不是统一截断所有 CU 的取值。

### 2.2 单个任务也不能用掉超过全 BS 的算力

记 CU 工作量 `W_j=C_j L_j`，UAV 感知工作量 `W_i=C_sen Q_i`。代码使用：

`f_cj = W_j/(D_j-c_j)`，`f_ui = W_i/(D_u-d_s-u_i)`。

因此必要上界为：

`c_j <= D_j-W_j/F_max`；

`u_i <= D_u-d_s-W_i/F_max`。

CU 上界只依赖当前任务与总算力，可以直接作为已有区间的必要条件收紧。UAV 的 Q_i 要在给定匹配、CU 功率及感知构造后确定；若使用预先下界，只能用经证明不大于实际工作量的乐观下界。

示例：`D_j=0.6s,L_j=150000bit,C_j=900cycle/bit,F_max=1e10cycle/s`，则 `c_j<=0.5865s`。再长时，即使把整台 BS 都分给此任务也不够。这是示例参数组合，不是把所有 CU 固定为同一个截止时间。

这些是必要条件，独立满足不保证总算力足够。不能任意把每个任务频率上限设成 `F_max/(I+J)` 并声称保留所有可行分配；原问题允许不均匀分配。更紧的必要上界可以扣除其他任务必需的最小算力，但必须使用有效下界，而非随意固定配额。

### 2.3 上传量产生与速率相关的下界

固定匹配、CU 功率、UAV 波束后，代码中的速率已确定。令 UAV 感知数据量为 Q_i，UAV 上传速率为 R_ui；则：

`u_i >= Q_i/R_ui`。

对唯一匹配的 CU j，代码给出的三阶段上传量为：

`B_j = d_s R_1ij + u_i R_2ij + (c_j-d_s-u_i)R_3j`。

因此：

`c_j >= [L_j+d_s(R_3j-R_1ij)+u_i(R_3j-R_2ij)]/R_3j`。

CU 的最终下界应同时取该式、新鲜度下界及实现的正数下界的最大值。未匹配 CU 的下界为 `L_j/R_3j`。若分母速率为零而任务量为正，该动作前缀不能通过调整时间实现上传。

这里的「前缀不能补全」只针对已选匹配、功率和波束；不等于整个状态下的 P0 都无解。更换前缀可能恢复可行性。

## 3. 更强的发现：当前模型允许解析消去时间动作

本节是基于当前代码的推导，不是从引用论文借来的定理。条件为：匹配不重复；状态、移动、CU 功率、卸载波束已固定；其他物理约束满足；速率和任务工作量固定且相应上传可定义；采用原硬约束而不是任意放宽的失败动作目标。

当前速率满足 `R_1ij<=R_3j`、`R_2ij<=R_3j`，因为前两阶段分母包含非负 UAV 干扰，第三阶段仅含噪声。因此 CU 时间下界关于匹配 UAV 的 u_i 单调不减。

先取 `u_i*=max(epsilon,Q_i/R_ui)`，再按第 2.3 节取每个 `c_j*` 的最大下界。由单调性，对任意可行时间向量 `(u,c)`，均有：

`u_i* <= u_i` 且 `c_j* <= c_j`。

由于各任务最小所需 CPU 频率随卸载时间单调增加，该分量最小时间向量也最小化总 CPU 需求：

`F_min = sum_i W_i/(D_u-d_s-u_i*) + sum_j W_j/(D_j-c_j*)`。

如果有非正剩余计算时间，或 F_min 已超过 F_max，则当前前缀没有任何可行时间分配。反之，若所有其他约束通过，该时间向量满足上传、新鲜度、时延及共享算力条件。相比单独裁出一个矩形，它真正检查了耦合关系。

固定其他动作后，代码的时间相关加权能耗为：

`E_time = omega_1*kappa*[sum_i W_i^3/(D_u-d_s-u_i)^2 + sum_j W_j^3/(D_j-c_j)^2] + omega_2*sum_i P_off_i*u_i + omega_3*sum_j p_j*c_j`。

各权重非负，因此能耗关于每个时间变量非减。分量最小的 `(u*,c*)` 也是该条件子问题的能耗最优解，无需 CCCP 或其他数值优化器。

当前 Pure 的时间不进入后续位置、位移、信道、任务序列或下一观测；其内部成功统计标志会改变，但当前 Pure 不将该标志用于未来奖励。因此，这一条件消元具有比单纯经验缩区间更强的依据。若后续加入任务队列、剩余电量、跨槽计算或成功回合奖励，应重新审查前提。

需要区分两种等价性：保留原硬约束问题的可行最优控制，不等于与允许付罚分换取低能耗的整个无约束罚函数 MDP 完全等价。对重复匹配或其他物理约束已失败的前缀，本节不作条件最优性保证。

## 5. 两条实现路线与建议顺序

路线 A：保留 14 个时间动作，用条件可行域解码。逻辑顺序为匹配及功率/波束 → 速率和任务工作量 → 时间下界与全局 CPU 可补全检查 → 在可行时间域内探索。要考虑共享 CPU；分别满足单变量区间不够。可按顺序解码，保留对其余任务最小算力的预留，必要时用单调一维求界；无需引入原内层大优化问题。

路线 B：按第 3 节解析产生时间，将 4 个 UAV 时间维和 10 个 CU 时间维从 actor 中移除，连续维度由 116 降至 102。这是更强的结构改进，应明确命名为含解析时间解码的变体；处理不可补全前缀时仍需定义有效策略或失败处理，不得伪装已满足约束。

若要保持纯策略自行学习时间的设定，先做路线 A，并与仅熵退火独立对照。若目标是尽量高效求解当前物理模型，且允许解析结构，路线 B 值得先实现和验证，再调整剩余动作头的探索。两者均优于没有证明的固定小盒裁剪。连续熵退火仍有意义，但不能替代物理可行域约束。

推荐对照为：原始基线、仅连续熵退火、仅条件时间解码、二者组合；解析消元另列一个变体。先保持学习率区间、数据预算和随机种子一致，使用原始随机策略 reward/完成率/能耗验收。当前未执行这些从头训练实验。

## 6. PPO 概率与公平比较

- 不应裁剪后把新动作当作原 Beta 样本，却继续使用未裁剪分布的 log-prob。可保留原始潜变量 z 与它的 log-prob，用固定、可复现的解码器 `a=g(s,z)` 执行；或者显式使用变换后的分布及必要的 Jacobian。旧/新策略评价和实际执行必须对应同一种动作定义。[1]
- 条件边界依赖动作前缀时，必须使用同一个状态和前缀重建；采样后反复重采样、投影或裁剪的分布都要明确，不能仅替换一个数值而忽略概率契约。
- 固定归一化潜变量熵与物理动作熵不是同一个量；条件区间宽度变化时，熵正则口径需要明确。解析移除时间头后也应同步移除其 log-prob 和 entropy 项，避免保留已无控制作用的维度。
- 对已知无效离散动作的 masking 有相关理论与实证工作，但不能用离散 masking 论文替代本系统连续可行域的推导。[2]

## 7. 已实现的保留时间头方案：代码位置与区间实数示例

当前训练代码已集成以下方案，新运行默认 conditional，旧配置缺省保持 legacy。保留全部 14 个时间动作；不同于第 4 节将时间直接替换为条件最短值的诊断，也不同于移除时间头的 102 维变体。

### 7.1 代码改动位置

- `physical.py`：在原链路速率计算后加入解码回调，随后使用执行时间继续原物理评价；复用同一次 MVDR 和速率计算，无需完整重复评价两次。保持原速率、约束、能耗和 reward 公式。
- `time_decoder.py`：实现有可行下端点的单调求界和共享算力预留；解析 CU 上界在浮点端点用实际总算力复核，必要时退回有界求界，不因消减误差将有效端点误判为不可补全。
- `pure_env.py`：保留 `_bounds()` 作为全局物理包络；在 `step()` 中先解码移动、功率、波束与匹配，再计算速率、条件解码时间，最后统一评价物理结果。新增时间解码 helper，不再将 14 个时间潜变量直接线性映射到独立旧区间。
- `Pure_MHBPPO_main.py` 的配置/日志：记录解码版本、解码顺序、当前条件上下界、是否存在时间可行补全及 BS 算力占用。实际执行与 checkpoint 评价必须使用相同的解码版本；旧运行保持 legacy 语义。
- `Pure_MHBPPO_agent.py`：保留 116 维连续输出和 4 个离散头；仍在归一化潜变量 z 上采样并计算 old/new log-prob。当前 sampler 已保存原始 z，可以继续采用该契约，不将物理时间反算为另一个 Beta 样本。

### 7.2 一个保证共享 CPU 可补全的顺序解码

先求全部最短时间，若其已不可行，则标记此前缀无法补全；不能用 epsilon 把空区间装作可行。下面只说明不重复匹配且最短时间可行的分支。

1. 按 UAV 编号 0–3 解码 u_i。已解码时间固定，未解码 UAV 暂取最短时间；CU 暂取随 u 变化的新鲜度/上传下界。对当前 u_i 用单调一维求界，找到仍满足所有截止时间与 `F_total<=F_max` 的最大 U_i；执行 `u_i=L_i+z_i*(U_i-L_i)`。
2. 固定全部 UAV 时间，重新计算 CU 最小时间。按 CU 编号 0–9 解码；此前 CU 使用已解码值，后续 CU 暂用最小值。令 `F_free=F_max-F_other`，则当前 CU 上界为 `U_j=D_j-W_j/F_free`，下界为上传/新鲜度下界；执行相同线性映射。
3. 日志记录每一步实际使用的条件区间。最终共享算力受联合约束控制，而不是只验证各个任务独立小于 F_max。解码顺序会影响采样分布，但不能将它误称为固定的全局小 box。
