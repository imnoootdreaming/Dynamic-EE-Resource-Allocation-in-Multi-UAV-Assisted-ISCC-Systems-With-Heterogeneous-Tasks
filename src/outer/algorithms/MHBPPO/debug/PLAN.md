# MHBPPO 后期重复匹配调试计划

保持四个离散头完整的 CU 动作空间，由网络学习避免重复匹配。训练使用 8 个环境的全部样本，按整批 320 个时隙报告原始平均 reward 和完成率。

## 1. 在 actor loss 中加入期望重复匹配惩罚

**状态：代码已实现，训练效果待验证。**

- 对每个状态和 CU，利用独立离散头的概率计算现有频谱惩罚 `max(选择次数 - 1, 0)` 的期望。对 CU 求和、对 minibatch 取平均，以可配置权重加入 actor loss。所有 CU 继续参与采样和 PPO 概率计算。
- 首次消融只开启期望惩罚，固定原有环境奖励、离散和连续熵系数、学习率、场景、种子及训练轮数。
- 参数 `--expected_duplicate_matching_coef` 默认 `0`，供基线使用。首次实验系数取 `0.1`，后续根据重复匹配率和能耗判断是否调权重。
- `mhbppo_train.log` 和 `training_updates.csv` 记录 `actor_expected_duplicate_matching`。该值是更新后 actor 在本批次状态上的期望惩罚均值。实际重复匹配率使用同一轮采样数据的 `spectrum_penalty_rate`（文本日志里的 `spectrum`）。关闭辅助损失时，期望值记为缺失。
- 本地 CPU 验证已通过。对照枚举的 81 种分配，核对了期望公式、四个离散头的梯度及原有 log-prob 和熵。合成批次上的一次 PPO 更新降低了期望惩罚。完整环境的训练效果等待新运行日志。
- 历史基线为运行 `2026-11-04_10-33-41` 的第 2501–3000 次更新。整批 `320/320` 全成功的更新有 `173/500`（34.6%），重复匹配涉及 `544/160000` 个时隙，内层无解涉及 `23/160000` 个时隙。验收目标为新运行最后 500 次更新至少 `401/500` 次整批全成功，同时比较实际重复匹配率、内层无解率、原始 reward 和能耗。
- 待用户提供新运行的 `mhbppo_train.log` 和 `training_updates.csv` 后，记录配置、指标变化及是否达到目标。

从仓库根目录启动首次消融。若历史基线使用了自定义配置，附上同一份 `--config`。

```bash
bash src/outer/algorithms/MHBPPO/run_background.sh start --max_updates 3000 --expected_duplicate_matching_coef 0.1
```

## 2. 将后期离散熵退火作为独立对照

**状态：待实施。**

- 关闭第 1 项辅助损失，仅在后期逐步降低离散熵系数。首轮候选为训练的最后 20% 内从 `0.01` 线性降到 `0.001`，连续熵系数和其余配置采用基线设置。
- 对同一批状态比较四个头各自 `argmax` 的重复率与随机采样的重复率。验收继续使用随机训练采样与第 1 项的同一指标口径。

## 3. 简化后台训练进度显示

**状态：已实现并用用户提供的日志样本验证。**

- `run_background.sh logs` 每轮显示平均奖励和近似耗时，耗时为等采样、详细日志写入和 PPO 更新三段之和。旧日志若仅有更新计时，则标为更新耗时。
- `run_background.sh logs-full` 跟踪原始文本日志，用于启动和异常排查。
- 进度行追加 `当前总耗时 HH:MM:SS`，从原始日志首条带时间戳的记录计至本轮更新。用日志尾部样本验证第 3 轮显示 `00:01:21`，另用跨日样本验证累计小时可超过 24。
- Bash 语法检查通过。2026-11-05 提供的第 1–3 轮日志分别显示奖励 `0.319`、`0.389`、`0.338`，耗时约 `30.6`、`24.3`、`25.1` 秒。此样本用于核对显示，后期训练效果仍按第 1 项验收。
