# 16736轮MHBPPO窗口困难原因分析

结论：并非每个窗口都难；前5窗口optimal=98.55/98.65/93.60/92.20/87.90%，第6=11.20%，第7–10=0%。关键链路是多UAV联合感知可行性、跨窗口预定位、失败奖励平坦和无效概率动作维度；CPU/环境运行成本导致38.77小时并不等于充足有效探索。所有成功判断仅按optimal。

## 3. 奖励与动作收益时序

my_env.py 550–565使用移动前信道求解，605–608之后才更新位置和信道；因此移动主要影响未来optimal，不改善当前求解。my_reward.py 91–100：失败energy=inf时exp(-inf/1000)=0，无冲突则reward=-1。第7–10窗99%以上奖励完全相同，没有感知margin/距成功差距反馈。共享全局奖励也不能告知哪台UAV/哪个头导致失败。critic仍可学习固定失败回报，但不能因此创造成功方向信号。

gamma=0.99,lambda=0.95，GAE递推对未来TD误差权重(0.9405)^k；k=8/16/24为0.612/0.375/0.229。这不是直接回报折扣或绝对有效规划长度，value bootstrap可传递长期信息；但与零成功尾部相结合，跨窗信用分配更困难。

## 4. 连续动作与PPO更新

实际alpha=0，80/102连续维度完全不影响执行接收波束；agent.py 178–186仍加总所有头logprob/entropy，403–412形成连续组ratio与entropy系数0.05。无效随机动作引入估计噪声与额外概率变化，不能断言期望梯度必然有偏。连续组logratio含80个无效维度，组clip可被这些维度共同影响；缺per-head clip数据，影响大小未定。

TensorBoard最新500轮：总连续微分熵−2.4682（初期−8.0923），离散熵1.28046（初期9.00173），Critic loss1.3788（上次2.0930），采样KL均值0.001630（上次0.002455）。KL单轮可为负、最大0.3559，是有符号小样本估计，不能说严格每轮KL稳定或用总量排除分头抵消。连续微分熵负值合法；归一化动作Uniform[0,1]熵0。各窗卸载时长raw SD约0.284–0.288，近Uniform[0,1]标准差0.288675；在此观测下持续探索强，熵权重抑制集中化是合理待检验原因，不是已证唯一根因。

代码分别clip连续/离散ratio，然后相加；联合策略ratio应为r_cont*r_disc，分别clip不是标准联合PPO同一目标。该分组方法可能是设计选择，需要消融验证，不能直接称代码错误。仅40条新transition/update，5 epochs×2 minibatches约10次优化，重复epoch不产生新环境状态；学习率iter9000之后为3e-5下限。

## 5. 40小时的去向

开始2026-10-09 18:43:56，到16736轮2026-10-11 09:30:15，共38.7718小时，669440环境步。日志cost包围agent.update，累计3141.138秒=52.35分钟，占2.2504%；其余含环境/内层求解、采样、队列、诊断序列化写盘等，不能全归MOSEK。单采样器同步无法用更多GPU直接消除每步内层代价。本运行env/actions已产生约21.5GB日志（精确冻结字节见summary），可能增加负担，但没有独立profiling证明是主因。16730轮起cost及UPDATE间隔骤升说明额外运行变慢，日志未给CPU/内存/调度原因。

## 6. 建议优先顺序

不再把单纯续训作为主要方案；保留checkpoint，先用固定500 episode评估各窗口。优先排除alpha0无效动作在sample/evaluate概率与entropy中的贡献（保持契约一致）。其次在固定位置做匹配/功率teacher/oracle对照，量化第6/7窗可恢复optimal；不能用感知候选替代实际重求解。再设计只引导跨窗可行性的密集信号/课程或可行示范，同时明确reward目标变化与PPO行为概率语义；不把teacher覆盖动作配原actor old-logprob入buffer。最后对连续熵、batch和学习率做同预算消融，分头记录KL/clip/adv/gradient。新增profiling区分solver/诊断/I/O/update，降低无必要诊断频率。

当前证据证明策略局部瓶颈，不证明全局100%不可能，亦未执行上述改造。
